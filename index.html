Planned projects

Agents & RAG

Twelve ideas for the next stage of my portfolio.
These are build plans; the apps are not implemented yet.

01Planned

Dynamic Context Assembler

Give an agent the context it needs without exceeding its token budget.

Build plan +

What I’ll build

A middleware layer that budgets tokens for instructions, retrieved documents, tool schemas, conversation history, and the model’s response. Keep required instructions intact and choose which evidence to include.

How I’ll test it

Check token limits across short and long tasks, compare against fixed-size context, and measure answer quality, evidence coverage, and cost.

02Planned

Hybrid Reranking Search Stack

Combine keyword search and semantic search, then rerank the results.

Build plan +

What I’ll build

BM25 retrieval alongside pgvector semantic search, result fusion, and a cross-encoder reranker. Use a clearly scoped document collection and a reproducible ingestion pipeline.

How I’ll test it

Evaluate Recall@k and nDCG on held-out queries. Compare keyword-only, vector-only, hybrid, and reranked results, including latency and cost.

03Planned

GraphRAG Knowledge Extractor

Connect facts scattered across documents through entities and relationships.

Build plan +

What I’ll build

Extract entities and relationships into Neo4j with links back to source passages. Add graph traversal for questions that genuinely need multiple documents.

How I’ll test it

Check extraction accuracy, source provenance, and multi-hop answer quality against a simpler retrieval baseline. Report when the graph does not help.

04Planned

Self-Correcting Agentic RAG

Retry retrieval when evidence is weak, and abstain when it stays insufficient.

Build plan +

What I’ll build

An answering workflow that grades retrieved passages, rewrites queries, and retries within a fixed budget. Return supporting citations or an explicit insufficient-evidence result.

How I’ll test it

Use answerable and unanswerable questions to measure grounded answers, citation correctness, false confidence, retry cost, and abstention behavior.

05Planned

Durable State Machine Workflow

Resume a long-running agent task after a restart or an external failure.

Build plan +

What I’ll build

A checkpointed Temporal or LangGraph workflow with typed state, bounded backoff, idempotent side effects, and an asynchronous approval step through Slack.

How I’ll test it

Stop and restart workers mid-task. Inject timeouts and duplicate events, then verify recovery, approval handling, and that external actions are not duplicated.

06Planned

Raw MCP Server & Client

Implement the protocol behind a tightly scoped Postgres tool integration.

Build plan +

What I’ll build

A protocol-learning project implementing MCP client/server messages over JSON-RPC without a wrapper SDK. Expose explicitly allowed database operations with argument validation and least-privilege credentials.

How I’ll test it

Exercise protocol negotiation and errors, validate messages against the specification, and verify that disallowed tables and operations cannot be accessed.

07Planned

3-Tier Memory & Eviction Engine

Keep useful context while giving memory a clear size and lifetime.

Build plan +

What I’ll build

Working memory for the current task, compressed episodic memory for sessions, and semantic memory for retrieval. Include capacity limits, TTL, ownership, and deletion rules.

How I’ll test it

Run long conversations and concurrent sessions. Measure retrieval usefulness and memory growth, and test stale-memory eviction and user isolation.

08Planned

Typed Multi-Agent Swarm

Let a researcher, coder, and reviewer hand off work through typed state.

Build plan +

What I’ll build

Three agents exchanging validated Pydantic objects rather than unstructured messages. Make responsibilities, shared context, termination, and retry limits explicit.

How I’ll test it

Compare task success, latency, and cost against a single-agent baseline. Inject malformed handoffs and check that invalid state is rejected.

09Planned

Trajectory Eval CI Gate

Test how an agent reaches an answer, not just the final text.

Build plan +

What I’ll build

A GitHub Actions evaluation that checks tool-call traces against permitted transitions, dependencies, task outcomes, and golden paths where ordering is required.

How I’ll test it

Verify that known regressions fail CI while alternative valid trajectories pass. Include forbidden tool use, skipped approvals, and incomplete tasks.

10Planned

Inter-Agent Security & PII Proxy

Limit sensitive data and untrusted instructions passed between agents.

Build plan +

What I’ll build

Tokenize sensitive fields, validate handoffs, and detect suspicious instructions. Enforce permissions in tools and data access as well; a prompt filter alone is not the security boundary.

How I’ll test it

Use an adversarial test set for data leakage, cross-user access, and prompt injection. Measure missed attacks and false positives, and document remaining limits.

11Planned

Semantic Cache & Routing Gateway

Choose an appropriate model and reuse answers only when it is safe to do so.

Build plan +

What I’ll build

A model gateway with workload-based routing, tenant-scoped semantic caching, cache invalidation, and bypass rules for sensitive or time-dependent requests.

How I’ll test it

Measure task quality, cost per successful task, p50/p95 latency, cache hit rate, and incorrect cache matches. Test that cached data never crosses user boundaries.

12Planned

Public Architecture Teardown

Publish three technical write-ups that explain the systems and their tradeoffs.

Build plan +

What I’ll build

Write about agent coordination, durable state and recovery, and RAG quality versus cost. Include diagrams, reproducible commands, implementation decisions, and measured results.

How I’ll test it

Make each write-up traceable to runnable code and an evaluation setup. Explain failures, alternatives considered, and which conclusions the results actually support.
